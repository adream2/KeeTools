## 一、整体分层

```
┌───────────────────────────────────────────────────────────┐
│  用户入口                                                  │
│  SEO / 公众号 / 社群 / 网盘合集包                           │
└───────────────────────┬───────────────────────────────────┘
                        ▼
┌───────────────────────────────────────────────────────────┐
│  网站前台（public/ + src/frontend/）                       │
│  首页 / 分类 / 搜索 / 工具详情 / 在线使用 / 网盘中间页       │
└───────────────────────┬───────────────────────────────────┘
                        ▼
┌───────────────────────────────────────────────────────────┐
│  后台管理（src/admin/）                                    │
│  工具 / 分类 / 网盘 / 离线包 / 统计 / 站点设置              │
└───────────────────────┬───────────────────────────────────┘
                        ▼
┌───────────────────────────────────────────────────────────┐
│  服务层（src/services/）                                   │
│  扫描器 / 统计 / 打包 / 网盘探活                            │
└───────────────────────┬───────────────────────────────────┘
                        ▼
┌───────────────────────────────────────────────────────────┐
│  数据层                                                    │
│  storage/app.db（业务）  storage/stats.db（统计，物理隔离） │
└───────────────────────────────────────────────────────────┘

════════════════════════════════════════════════════════════════
  独立层：工具本体（tools/）
  - 单文件 HTML，资源内联，零外部依赖
  - 数据持久化仅用 localStorage
  - 不与网站后端通信
  - manifest.json 是与网站的唯一契约
════════════════════════════════════════════════════════════════
```

**核心设计**：网站与工具**单向依赖**。网站读取工具的 `manifest.json` 并提供分发；工具对网站一无所知。

## 三、请求流程

### 3.1 前台页面请求

```
浏览器
  → public/index.php
  → bootstrap.php（加载 .env / Config / 路由表 / DB 连接）
  → Router 匹配
  → 中间件链（前台：仅 Csrf；后台：Session → Auth → Role → Csrf）
  → Controller
  → Service（按需，如 ToolScanner）
  → Database（PDO 参数化查询）
  → View 渲染
  → Response 输出
```

### 3.2 工具扫描流程

```
后台点击"扫描同步"
  → ToolScanner::scan()
  → 遍历 tools/*/manifest.json（跳过 _shared/）
  → 校验字段完整性 + id 与目录名一致
  → 读取 index.html 中的 ET-META，比对 version
  → upsert 到 tools 表（保留 DB 侧的用户态字段：featured / sort / publish）
  → 返回差异报告（新增 / 更新 / 版本不一致 / 字段错误）
```

### 3.3 在线使用工具（含统计注入）

```
浏览器访问 /tool/{id}/use
  → ToolController::use()
  → 读取 tools/{id}/index.html 全文
  → 在 </body> 前注入统计脚本（独立 IIFE，不依赖工具代码）
  → 输出（Content-Type: text/html）
```

> 下载的单文件**不经此流程**，因此保持绝对干净。

### 3.4 统计上报

```
页面注入的脚本 → POST /api/track
  → StatsService::track()
  → 只写 append-only 日志（var/tmp/stats_buffer.log）
  → 定时任务（每分钟）批量落库到 storage/stats.db
```

## 四、关键机制

### 4.1 manifest 是唯一真源

| 操作 | 行为 |
|---|---|
| 后台编辑工具元数据 | **回写 `tools/{id}/manifest.json`**（`JSON_PRETTY_PRINT \| JSON_UNESCAPED_UNICODE`） |
| DB 存什么 | ① 索引（供查询排序）② 统计 ③ 纯用户态字段（featured / sort / publish / 网盘链接） |
| 扫描同步 | 以 manifest 为准更新索引，**不覆盖**用户态字段 |
| `tools/` 不可写 | 降级为写 DB override 表，后台提示降级模式 |

**为什么**：避免"库里的描述和文件里的描述不一致"这种必然发生的分歧。改动就在文件里，整包拷走即可完整迁移，且可 git 版本化。

### 4.2 工具与网站的契约

唯一的契约面就是 `manifest.json`。除此之外：

- 工具不 import 网站任何资源
- 工具不发任何请求给网站
- 网站不向工具传任何参数（`postMessage` 为可选，需工具自带默认值）
- 统计由网站**服务端注入**，工具无感知

### 4.3 `_shared/` 同步机制

见 [`工具开发规范.md`](工具开发规范.md) 与 `AGENTS.md` §3.6。

### 4.4 SQLite 并发策略

| 措施 | 配置 |
|---|---|
| WAL 模式 | `PRAGMA journal_mode=WAL` |
| 超时等待 | `PRAGMA busy_timeout=5000` |
| 统计物理隔离 | `storage/stats.db` 独立文件 |
| 写入缓冲 | 请求只写日志，每分钟批量落库 |
| 外键 | `PRAGMA foreign_keys=ON` |

## 五、扩展点

| 扩展点 | 位置 | 说明 |
|---|---|---|
| 新增页面 | `src/routes.php` + `src/frontend/Controller/` | 加路由 + 加控制器 + 加视图 |
| 新增后台模块 | `src/admin/Controller/` | 加控制器 + 视图 + 路由 |

| 更换数据库 | `src/core/Database.php` | 只改这一个类 + 写迁移脚本 |
| 切换 CSS 方案 | `assets-src/css/` | 只替换该目录产出，不影响其他架构 |

## 六、不做的事（明确边界）

| 不做 | 原因 |
|---|---|
| ORM / DB 抽象层 | YAGNI，SQLite → MySQL 用一次性迁移脚本更划算 |
| 前端框架（Vue/React） | 网站 UI 复杂度不需要，避免构建链 |
| Composer / npm 依赖 | 零外部依赖原则 |
| 工具与网站的 RPC 通信 | 解耦原则，manifest 已足够 |
| 工具内部统计 | 数据来自工具本身，统计只到"被打开"层级 |
| 用户系统（P0-P4） | 已取消（2026-09-19）：P5 不预建，按运营数据再评估 |

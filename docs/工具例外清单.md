# 工具例外清单

> 记录**无法做到单文件**的工具，以及对应的理由与处理方式。
> 配套：[`工具开发规范.md`](工具开发规范.md) §3.1、[`manifest规范.md`](manifest规范.md)
> 最后更新：2026-09-18

---

## 一、规则

单文件是**默认要求**，但非绝对。仅当以下情况才允许例外：

| 情况 | 说明 |
|---|---|
| 大体积素材 | 高清图 / 音频 / 视频，内联后体积不可接受 |
| WebAssembly | 需要 WASM 模块（如物理引擎、图像处理） |
| 大型数据集 | > 1MB 的 JSON，内联会显著拖慢加载 |
| 性能原因 | 内联后首屏明显卡顿 |

**例外必须全部满足**：

1. `manifest.json` 中 `single_file` 设为 `false`
2. `dependencies` 逐项声明实际使用的本地资源
3. 在本文件登记
4. 离线包打包时**整目录打包**（不能只打 `index.html`）
5. 在工具 `README.md` 说明为何无法单文件

> ⚠️ **例外是例外**。如果发现例外越来越多，说明单文件假设本身有问题，应重新评估架构而非持续破例。

## 三、登记模板

新增例外时复制以下内容：

```markdown
| `{tool-id}` | `{version}` | `YYYY-MM-DD` | 原因（一句话） | `assets/xxx`、`assets/yyy` | 约 X MB | 补充说明 |
```

并在工具的 `manifest.json` 中：

```json
{
  "single_file": false,
  "dependencies": ["assets/model.bin", "assets/textures/"]
}
```

## 四、对分发的影响

非单文件工具在分发时需特殊处理：

| 环节 | 处理 |
|---|---|
| 在线使用 | 正常，iframe 加载 `index.html`，相对路径由 Web 服务器解析 |
| 单文件直接下载 | ❌ **不可用**（无法下载"一个文件"） |
| 离线包 | ✅ 打包**整个工具目录**，保留目录结构 |
| 后台详情页 | 需提示"此工具非单文件，请下载合集包" |

**前台展示规则**：

- `single_file: true` → 显示"下载本工具"按钮
- `single_file: false` → **隐藏**"下载本工具"按钮，仅提供合集包入口

## 六、体积超限登记（单文件，但 `index.html` > `TOOL_MAX_KB`）

P4 起 `check_manifest.py` 对单个工具 HTML 做体积守卫（默认 **500KB**，可用环境变量
`TOOL_MAX_KB` 覆盖）。超限只**告警不拦截**，但超限工具必须在此登记，写清"为什么不能瘦身"。

处理优先级：

1. 先看共享逻辑能否抽到 `tools/_shared/`（消除多工具重复内联）
2. 再看内置数据能否改为「渲染器 + 可替换数据文件」（> 500 条即不算工具）
3. 都不行（如内嵌音频/图形素材）→ 在此登记，并在工具 `README.md` 说明

| 工具 id | 版本 | 登记日期 | 体积 | 超限原因 | 跟进 |
|---|---|---|---|---|---|
| `pinyin-chart` | `1.4.0` | 2026-09-18 | 约 768KB | 内嵌 183 个真人录音 mp3（audio-cmn，CC BY-SA）保证离线点读；音频是工具核心能力，无法外置（外置即失去单文件与 `file://` 可用性） | 若后续支持"音频按需加载"再评估 |

## 七、定期复核

每完成一个阶段（Px）时复核本清单：

- [ ] 例外项是否仍必要？（是否有新技术可回归单文件）
- [ ] 例外项数量是否超过工具总数的 20%？
- [ ] 例外项是否有共同模式，可提炼为新的架构方案？
- [ ] 体积超限项是否仍无法瘦身？（共享逻辑是否已抽干净）

> 若例外超过 20%，应暂停新增工具，先解决架构问题。

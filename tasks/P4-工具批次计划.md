## 二、现行标准速查（每个工具都必须满足）

### 2.1 生成方式（禁止手抄）

```bash
python scripts/new_tool.py --id <id> --title "<标题>" \
    --type <shell|fixed|experiment> --subjects <学科> --grades <学段> \
    --description "<≤60 字简介>" --family <family> --yes
```

脚手架自动完成：模板渲染 → 登记 `shared.manifest.json` → 内联共享片段 → 双自检 + 体积守卫。

- id：**kebab-case 全小写**，语义英文（`times-table` 而非 `chengfakoujue`）
- `family`：同一玩法的不同版本才填（如 `random-name`），否则留空
- 名单/词表类 `shell` 工具**必须复用 `et-import`**（粘贴 / CSV / 编码识别 / 去重）
- `accent` 按学科自动选取，同批内避免重复

### 2.2 每批自检（缺一不可）

```bash
# 1) 六项门禁
python scripts/check_manifest.py
python scripts/check_no_external.py
python scripts/sync_shared.py --check
python scripts/check_css_tokens.py
python scripts/build_css.py --check
python scripts/icons/build_sprite.py --check

# 2) JS 语法抽检（门禁抓不到，必做）
#    抽 <script> 块 → node --check；本机 Node v26 可用
#    重点验：代码示例里的 ET:INLINE 文本、script 结束标签字面量（见 规范 §6.4.1）

# 3) 入库
php scripts/init_db.php            # 首次
# 后台「扫描同步工具」或等价 CLI 扫描；确认 failed = 0、warnings = 0
```

## 五、数据体量红线（`fixed` 型最容易踩）

- 单个 `fixed` 工具**内置数据 ≤ 500 条**；超过即不算工具，改「渲染器 + 可替换数据文件」
- 体积红线 500KB（`TOOL_MAX_KB`）：超了先抽共享逻辑 → 再考虑数据外置 → 都不行才登记例外清单
- 批量导入型数据（词库、题目）一律走 `et-import`，**不写死进 HTML**

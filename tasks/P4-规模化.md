## 风险与备注

| 风险 | 应对 |
|---|---|
| **批量生产导致规范漂移** | 强制走 `new_tool.py` 脚手架 + pre-commit 校验，禁止手抄复制 |
| 工具同质化（同一功能做 10 个变体） | `family` 关联；只在样式/数据/玩法确有差异时才做独立工具 |
| 共享逻辑被绕过手工内联 | `sync_shared.py --check` 进 pre-commit；发现即失败 ✅ |
| 零使用工具堆积 | 每季度清理，不看数量看使用率（看板已提供清单） |
| SEO 垃圾页（搜索页/归档页被索引） | `/search` 与 `/tool/{id}/v/*` 一律 `noindex` ✅ |
| 体积膨胀拖慢首屏 | 详情页 iframe 懒加载；静态资源走缓存头；单工具 500KB 守卫 ✅ |

### 已决策（2026-09-18 P4 收尾）

- ✅ **不引入 CI**：单人开发，发布链路是 `git push relay → WinSCP 增量上传`，CI 覆盖不到部署
  自检；本地 `pre-commit` 六项门禁 + 每批手工验收为准。有协作者时再评估。
- ✅ **工具总数软上限 = 100**：超过后维护成本（manifest 回写、体积、SEO 内容、季度复核）
  超过收益，届时改为"只优化不新增"。
- ✅ **不做"用户提交工具"入口**：V1 无用户系统（P5 才评估），且需人工审核与责任归属，
  现阶段用「工具定制需求入口」承接需求即可。
- ✅ **`hello-keetools` → 改造为 `tool-template`「工具模板示例」**（v1.0.0，`stats_enabled: false`）。
